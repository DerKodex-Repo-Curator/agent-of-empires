# Prior PR decisions for the Daemon/client split

Research note for [#4396](https://github.com/agent-of-empires/agent-of-empires/issues/4396), part of epic [#2734](https://github.com/agent-of-empires/agent-of-empires/issues/2734). It records which design decisions [#4009](https://github.com/agent-of-empires/agent-of-empires/pull/4009), [#4011](https://github.com/agent-of-empires/agent-of-empires/pull/4011) and [#4136](https://github.com/agent-of-empires/agent-of-empires/pull/4136) each embed, the rationale their authors gave, and where they contradict each other or the three closed decisions [#3838](https://github.com/agent-of-empires/agent-of-empires/issues/3838), [#3839](https://github.com/agent-of-empires/agent-of-empires/issues/3839) and [#3840](https://github.com/agent-of-empires/agent-of-empires/issues/3840). It feeds [#4398](https://github.com/agent-of-empires/agent-of-empires/issues/4398) (crate shape), [#4399](https://github.com/agent-of-empires/agent-of-empires/issues/4399) (local transport and disk fallback) and [#4400](https://github.com/agent-of-empires/agent-of-empires/issues/4400) (CLI writes).

Researched 2026-10-13. Code citations pin the PR heads of that day: #4009 at `efa4305a`, #4011 at `478adf56`, #4136 at `6632a313`. #4009 and #4011 are experiments to mine, not merge candidates; #4136 is the baseline ([#2734 plan](https://github.com/agent-of-empires/agent-of-empires/issues/2734), [#4393](https://github.com/agent-of-empires/agent-of-empires/issues/4393)).

## The closed decisions, as ratified

The proposal is [#2734 comment 5626207757](https://github.com/agent-of-empires/agent-of-empires/issues/2734#issuecomment-5626207757) (jerome-benoit) and the ratification with three amendments is [#2734 comment 5635868081](https://github.com/agent-of-empires/agent-of-empires/issues/2734#issuecomment-5635868081) (njbrake). The closing comments on each ticket restate them.

| Decision | Ratified content |
| --- | --- |
| D1 / #3839 transport and auth | DF-A(a): same REST+WS routes and wire models over a local Unix socket and remote TCP; no second JSON-RPC protocol. DF-E(a): filesystem restrictions plus kernel peer credentials, no bearer on UDS; socket parent 0700, socket 0600; both ends verify peer effective UID; "Linux/macOS peer credential implementations belong in src/process". Errors classify from status plus the `AoE-Error-Code` header, never a body read. D1b amendment: the non-loopback plaintext 426 gate ships on by default with an explicit per-bind opt-out. No automatic replay of uncertain mutations. |
| D2 / #3838 lifecycle and offline | Daemon mandatory at final cutover, auto-started by the TUI, detached and shared across TUI exits, core UDS listener only by default, one daemon per application/build namespace spanning profiles, no idle exit. D2b amendment: DF-D(b), hard fail with reconnect guidance when unreachable, "not the stale snapshot and no on-disk cache". #3841's e2e must be rewritten to assert hard fail. |
| D3 / #3840 tmux ownership | DF-F(a) with writable TUI attachment preserved: the Daemon owns AoE-managed agent and auxiliary pane lifecycle, environment sync and status publication; the TUI keeps paint, keys, attach and pane I/O. DF-H(a): canonical visibility is authorization-scoped, never owned by a client id; event replay uses a server-issued cursor. Pane environment resolves from the Daemon host and needs an explicit restart to change. |

The ratification also records a gap the slices do not cover: "Nothing in the filed slices covers reaching a daemon from another machine beyond `AOE_DAEMON_URL` and `AOE_DAEMON_TOKEN`", to be folded into #3340.

## Rationale per decision, with sources

### Local transport

- **#4009** exposes "the native runtime through the private Unix API without requiring the web dashboard" ([PR body](https://github.com/agent-of-empires/agent-of-empires/pull/4009)). Its api.md adds: "The private local Unix socket verifies its owner instead. A native client using that socket does not need the TCP passphrase or a loopback login, including when the dashboard runs behind a proxy" (`docs/api.md` on `efa4305a`). The runtime stream frames are defined in [`src/daemon/runtime.rs`](https://github.com/agent-of-empires/agent-of-empires/blob/efa4305abf6f40ba26f726d0cfa98f8441278295/src/daemon/runtime.rs#L7-L24): `RUNTIME_PROTOCOL_VERSION = 2`, the two headers, `RuntimeCursor`, `MutationReceipt<T>`, `RuntimeFrame`.
- **#4011** documents the three surfaces in `docs/development/internals/client-transports.md` (on `478adf56`): REST on `/api/*`, the runtime stream on `/api/runtime/ws` ("the daemon serializes each revision once and fans it out"), and the live pane stream on `/sessions/{id}/live-ws`, kept separate because "folding it into the runtime stream would put one pane's output on the path that carries every session's state". Its `client-transports-evaluation.md` compares gRPC-Web, Connect, WebTransport and SSE against plain-HTTP LAN, Funnel and iOS Safari constraints and concludes "Keep WebSocket for all three surfaces"; the schema half recommends ts-rs, now filed as [#4032](https://github.com/agent-of-empires/agent-of-empires/issues/4032).
- **#4136** publishes a UDS on Linux only: the client's served path is under `#[cfg(target_os = "linux")]` and the `not(target_os = "linux")` arm returns `marker_missing`, which is the disk-fallback code ([`src/cli/runtime_read/mod.rs:263-294`](https://github.com/agent-of-empires/agent-of-empires/blob/6632a3139c4e0328986e06fd972939e4de4da479/src/cli/runtime_read/mod.rs#L263-L294)); `src/process/mod.rs:57` re-exports `linux::runtime_io` and `src/process/macos.rs` has no peer-credential helper. The route is a one-shot read: "Read-only runtime read: one Hello, one Snapshot, one clean close" ([`src/server/router.rs:76-77`](https://github.com/agent-of-empires/agent-of-empires/blob/6632a3139c4e0328986e06fd972939e4de4da479/src/server/router.rs#L76-L77)), `PROTOCOL_VERSION = 4` and a 15 s `CONNECTION_BUDGET` ([`src/server/runtime_ws.rs:34-36`](https://github.com/agent-of-empires/agent-of-empires/blob/6632a3139c4e0328986e06fd972939e4de4da479/src/server/runtime_ws.rs#L34-L36)). The contract is in `docs/api.md` "Runtime CLI reads" on `6632a313`. The reviewer's verdict proposed dropping "the UDS marker/ACL/flock layer (loopback HTTP with the 0600 token file covers the local case, macOS included)" ([review](https://github.com/agent-of-empires/agent-of-empires/pull/4136#pullrequestreview-5425247409)); the author kept it: "The Linux UDS default-discovery design and existing branch name are also retained" ([follow-up](https://github.com/agent-of-empires/agent-of-empires/pull/4136#issuecomment-6049215138)). The author's stated reason for the marker and admission layer is safety against untrusted artifacts: "Untrusted artifacts refuse; absent or provably dead publication permits disk fallback" ([`uds.rs:170`](https://github.com/agent-of-empires/agent-of-empires/blob/6632a3139c4e0328986e06fd972939e4de4da479/src/cli/runtime_read/uds.rs#L170)).

### Local auth

- **#4009**: "Derive local-owner authority from Unix peer credentials, not client claims or TCP loopback ... Processes sharing the owner UID are trusted; this is not daemon-instance authentication" ([PR body](https://github.com/agent-of-empires/agent-of-empires/pull/4009)). Code: `unix_peer_uid` in [`src/process/linux.rs:41`](https://github.com/agent-of-empires/agent-of-empires/blob/efa4305abf6f40ba26f726d0cfa98f8441278295/src/process/linux.rs#L41) and [`src/process/macos.rs:38`](https://github.com/agent-of-empires/agent-of-empires/blob/efa4305abf6f40ba26f726d0cfa98f8441278295/src/process/macos.rs#L38), the `UnixOwner(u32)` authorization in [`src/server/auth.rs:367`](https://github.com/agent-of-empires/agent-of-empires/blob/efa4305abf6f40ba26f726d0cfa98f8441278295/src/server/auth.rs#L367) and the client-side server-UID check in [`src/daemon/transport.rs:103`](https://github.com/agent-of-empires/agent-of-empires/blob/efa4305abf6f40ba26f726d0cfa98f8441278295/src/daemon/transport.rs#L103). The reviewer rated "SO_PEERCRED owner listener", "0700/0600 socket and app-dir checks" and "Client-side server uid check" as sound ([review](https://github.com/agent-of-empires/agent-of-empires/pull/4009#pullrequestreview-5425245503)) and asked that docs not describe the namespace/tmux checks as daemon-instance authentication ([second review](https://github.com/agent-of-empires/agent-of-empires/pull/4009#pullrequestreview-5487507015)). A passphrase-wall bypass behind an unflagged loopback proxy was a blocker and is reported fixed by failing closed when a loopback peer sends forwarding headers ([thread](https://github.com/agent-of-empires/agent-of-empires/pull/4009#discussion_r4192733737)).
- **#4136**: Linux peer credentials via `SO_PEERCRED` ([`src/process/linux.rs:680-699`](https://github.com/agent-of-empires/agent-of-empires/blob/6632a3139c4e0328986e06fd972939e4de4da479/src/process/linux.rs#L680-L699)), checked by the client in [`uds.rs:811-816`](https://github.com/agent-of-empires/agent-of-empires/blob/6632a3139c4e0328986e06fd972939e4de4da479/src/cli/runtime_read/uds.rs#L811-L816). The first head hard-failed reads on group-writable HOME and under `sudo`; the follow-up relaxed it so "Artifact-free namespaces preserve local reads with group-writable or foreign-owner HOME; published artifacts still require strict admission". A "bearer-only" header-shape check was dropped; "Runtime HTTP uses the existing daemon authenticator, including cookies/passphrase sessions" ([follow-up](https://github.com/agent-of-empires/agent-of-empires/pull/4136#issuecomment-6049215138)). The CLI reference still says "TUI session-list authentication supports bearer tokens only" (`docs/cli/reference.md:180` on `6632a313`), which is a different surface.

### Remote transport and the 426 gate history

- **#4009** early heads carried a server-side gate returning 426 for non-loopback plaintext. njbrake asked on 2026-09-17 to "drop the plaintext 426 gate in `src/server/access.rs:308-320`, or make it opt-in", because "Main serves the dashboard over plain HTTP on a LAN or tailnet ... TLS on a trusted network is the operator's call" ([comment](https://github.com/agent-of-empires/agent-of-empires/pull/4009#issuecomment-5713214718)). At the current heads of **both #4009 and #4011** no `426`, `tls_required` or `UPGRADE_REQUIRED` token exists in `src/server/access.rs` (grep on `efa4305a` and `478adf56`). The client-side rule survives in #4009: "Native credential-bearing HTTP requires HTTPS outside loopback, disables redirects and bypasses proxies for local connections" ([PR body](https://github.com/agent-of-empires/agent-of-empires/pull/4009)).
- The ratified **D1b** is the opposite default: "Ships on by default with an explicit per-bind opt-out, named so nobody sets it by accident, logged at every startup, never inferred from the address ... Needs a minor release and release notes" ([ratification](https://github.com/agent-of-empires/agent-of-empires/issues/2734#issuecomment-5635868081)). The same comment accepts that `tailscale serve` and Funnel are unaffected because TLS terminates ahead of a loopback listener.
- **#4011** treats plaintext LAN as a product feature: `docs/guides/remotes.md` on `478adf56` says a LAN, link-local, tailnet or `.local` address "is reached over plain HTTP", `aoe remote add` asks before sending credentials over plain HTTP and `--insecure` stores that answer "on that entry only"; `Remote.insecure` is in [`src/daemon/remotes.rs:37-39`](https://github.com/agent-of-empires/agent-of-empires/blob/478adf569277a981d1c896407901e4e5a396bb95/src/daemon/remotes.rs#L37-L39).
- **#4136** requires HTTPS for runtime reads "except for loopback literals and `localhost`, which the read client pins to loopback without DNS" (`docs/structured-view.md:141` on `6632a313`). The reviewer noted `http://localhost:8080`, accepted by the TUI and `aoe acp`, was rejected as `invalid_endpoint` on the first head ([thread](https://github.com/agent-of-empires/agent-of-empires/pull/4136#discussion_r4192735031)); the follow-up pinned `localhost` to loopback instead of rejecting it.

### Remote auth and the registry

- **#4011** is the only PR with a registry. `remotes.rs` header: "Lives at `<app_dir>/remotes.toml`, owner-only, alongside the other ... token and, for a daemon behind a passphrase wall, a login session and its device-binding secret. The passphrase itself is never stored" ([`src/daemon/remotes.rs:3-6`](https://github.com/agent-of-empires/agent-of-empires/blob/478adf569277a981d1c896407901e4e5a396bb95/src/daemon/remotes.rs#L3-L6)); the file is forced to 0600 on save (`:279`) and refuses a newer schema (`:260`). Pairing: "Pairing needs no token. The code is single use and valid for 10 minutes ... The entry stores a device-bound session instead of a token, so rotating the remote's token or changing its passphrase does not affect it" (`docs/guides/remotes.md`). The guide also fixes which actions have no remote counterpart (Add project, Fork, view switch) because each "would answer from this machine rather than the one that owns the row", and that hooks are never approved remotely (HTTP 403 until trusted on that machine).
- **#4136** reuses the ACP client's passphrase session cache: "These clients share the `/api/login` handshake, device binding, and persisted session cache ... a failed authentication never substitutes local rows" (`docs/structured-view.md:143`).
- The ratification left remote access to #3340 and the epic lists "Remote authentication beyond passphrase (passkeys #4348)" as unspecified, so nothing in #4011's pairing design is ratified or contradicted.

### Snapshot and revision model

- **#4009**: "Stream epoch/revision snapshots over WebSocket and return mutation receipts. The TUI waits for a same-epoch snapshot at or beyond the receipt and blocks unknown outcomes without local fallback or automatic replay; clients reject stale state" ([PR body](https://github.com/agent-of-empires/agent-of-empires/pull/4009)). api.md: "`aoe-runtime-epoch` and `aoe-runtime-revision` identify the exact returned snapshot ... A stale list must not replace newer canonical rows or ordering." The reviewer rated "Revision monotonicity (`publish_lane` plus `checked_add`)" and "Per-daemon epoch UUID: clients compare the epoch before the revision, so a daemon restart cannot freeze them" as sound, and asked for a request or idempotency key on `MutationReceipt<T>`, which "carries only cursor and outcome" ([second review](https://github.com/agent-of-empires/agent-of-empires/pull/4009#pullrequestreview-5487507015)).
- **#4011** explains why remotes poll: "`RUNTIME_PROTOCOL_VERSION` is enforced by exact equality during the stream's handshake, while the REST endpoints are version tolerant ... A *remote* daemon is another machine ... routinely a different build. Moving the remote read path onto the stream as it stands would make a version skew fatal where it is currently invisible" (`client-transports.md`). It proposes stream-with-polling-fallback and subprotocol version negotiation as the fix.
- **#4136** carries the same cursor shape in the snapshot: `cursor { epoch: uuid, revision >= 1 }` ([`tests/fixtures/cli-read/snapshot.schema.json:157-163`](https://github.com/agent-of-empires/agent-of-empires/blob/6632a3139c4e0328986e06fd972939e4de4da479/tests/fixtures/cli-read/snapshot.schema.json#L157-L163)) plus per-store `revision` and `observed_at` health, and a `Hello` with `protocol_version`, `runtime_epoch`, `namespace`, `owner`, `local_owner`, `health`, `profiles`, `status_freshness` ([`hello.schema.json:7-18`](https://github.com/agent-of-empires/agent-of-empires/blob/6632a3139c4e0328986e06fd972939e4de4da479/tests/fixtures/cli-read/hello.schema.json#L7-L18)). The api.md contract adds a stricter JSON rule than the CLI: "Where a wire schema allows `null`, the member must still be present. Omitting a required member is `schema_invalid`."

### Fallback policy

- **#4009** implements D2b: "The TUI starts or reuses the local Core through its private Unix socket ... If startup or connection fails, the TUI shows the diagnostic and masks daemon-owned session state. Press `r` to reconnect or retry local startup after fixing the cause, or `q` to quit" (`docs/guides/web-dashboard.md` on `efa4305a`). The first review found "two lifecycle writers" because `local_write_block` admitted TUI trash, purge and group writes while a healthy daemon owned the rows ([thread](https://github.com/agent-of-empires/agent-of-empires/pull/4009#discussion_r4192733764)); the author reports at `c57d62c0` that "Trash, purge, restore, groups, profiles, and other native mutations go through daemon commands. The TUI projection is read-only" ([reply](https://github.com/agent-of-empires/agent-of-empires/pull/4009#discussion_r4216606167)). Not re-verified at line level here.
- **#4136** states its rule in the module header and the CLI reference: "Explicit endpoints never fall back. Environment endpoints do so only before a peer is reached" ([`mod.rs:246-252`](https://github.com/agent-of-empires/agent-of-empires/blob/6632a3139c4e0328986e06fd972939e4de4da479/src/cli/runtime_read/mod.rs#L246-L252)); "`AOE_DAEMON_URL` selects the same endpoint, but an absent peer falls back to the local store with a notice on stderr after at most one second of TCP discovery ... Without an HTTP endpoint, Linux uses an admitted local daemon socket when published, otherwise the local store. Other platforms use the local store" (`docs/cli/reference.md:180`). The PR body frames this as preserving today's behavior: "Local reads remain available when no runtime artifacts exist; other platforms default to local storage." The reviewer's verdict went further the other way: "keep disk reads as the local default; serve remote reads through the existing authenticated HTTP route" ([review](https://github.com/agent-of-empires/agent-of-empires/pull/4136#pullrequestreview-5425247409)). Neither position is D2b.

### Daemon lifecycle

- **#4009** auto-spawns `serve --daemon-child --core-only` under `setsid` with no idle exit (reviewer: "an undocumented persistent core daemon is auto-spawned", [thread](https://github.com/agent-of-empires/agent-of-empires/pull/4009#discussion_r4192733783)); `core_only` and `daemon_child` are launch-record fields in [`src/cli/serve.rs:42-176`](https://github.com/agent-of-empires/agent-of-empires/blob/efa4305abf6f40ba26f726d0cfa98f8441278295/src/cli/serve.rs#L42-L176). The dashboard guide documents `--core-only --daemon`, the lifecycle lock, `--restart`, `--rollback` and that "An explicit `aoe serve` request replaces an existing managed core under the daemon lifecycle lock" (on `efa4305a`). This is D2 as ratified, including "the detached daemon persists when the initiating TUI exits".
- **#4136** never starts a Daemon from the CLI. Its startup fix after review: "Publication waits cancellably for shared readers/probes. A separate exclusive `publisher.lock` stays held across the lifetime-lock downgrade" ([follow-up](https://github.com/agent-of-empires/agent-of-empires/pull/4136#issuecomment-6049215138)), addressing the reviewer's `namespace_busy` race ([thread](https://github.com/agent-of-empires/agent-of-empires/pull/4136#discussion_r4192735044)).

### tmux ownership

- **#4009** routes "paired terminal/tool management" through the runtime and "Auxiliary teardown targets the owned pane without stopping the agent" ([PR body](https://github.com/agent-of-empires/agent-of-empires/pull/4009)). Pre-upgrade tool panes lacking `@aoe_tool_owner` could not be killed; the fix adopts legacy panes "using immutable canonical ownership, pane/PID/SID/generation identity, multi-profile validation, and marker CAS" ([reply](https://github.com/agent-of-empires/agent-of-empires/pull/4009#discussion_r4216605807)). This is D3's DF-F(a).

## Contradictions to resolve

1. **Disk fallback versus D2b (#4399, #4400).** #4136 reads the on-disk store on non-Linux, on Linux when no publication is admitted, and when `AOE_DAEMON_URL` gets no TCP answer within 1 s. #3838 ratified "hard fail with reconnect guidance, not the stale snapshot and no on-disk cache". #4399 must say whether #4136's fallback is transitional for read-only commands (and what removes it) or a violation; #4400 inherits the answer for writes.
2. **Platform scope of the UDS (#4399).** #4136 publishes and admits a UDS on Linux only, with no macOS peer-credential helper. D1 says "Linux/macOS peer credential implementations belong in src/process", and #4009 already has `unix_peer_uid` for both platforms. Either #4136 gains the macOS leg from #4009 or D1 is amended to Linux-first.
3. **The 426 plaintext gate (#4399, security default).** D1b ratified the gate on by default with a named per-bind opt-out. Both experiment heads dropped it after njbrake's #4009 comment, and #4011's remotes guide makes plaintext LAN a documented, per-entry `--insecure` choice. One of the two positions has to move: the ratification text, or the product stance njbrake took on #4009 and #4011.
4. **One route, two protocols.** #4009 and #4011 use `/api/runtime/ws` for a versioned push stream (`RUNTIME_PROTOCOL_VERSION = 2`, exact-match handshake, receipts). #4136 uses the same path for a one-shot `Hello` + `Snapshot` read at `PROTOCOL_VERSION = 4`. Porting #4009 onto #4136 means deciding whether the CLI read is the first frame of the stream (as #4011's `/api/runtime/snapshot` suggests) or a separate endpoint, and whether version negotiation is exact (#4009) or tolerant with fallback (#4011's argument for remotes).
5. **Migrations versus "no schema change".** The epic's original proposal assumed no on-disk schema change; #4009 needs twelve migrations and #4011 five, for launch records, passphrase policy, purge ownership and sidebar canonicalization. #4136 needs none. The crate-shape and write-path tickets should state which of those persisted records (managed launch, purge journal, canonical ordering) the baseline will adopt.
6. **CLI projection shape (#4400).** #4136 sends every session's `command` and alias-only rows over the runtime read "under daemon-wide credentials, not profile ACLs", which the reviewer called a third session projection beside `cli/list.rs` and REST `SessionResponse`; the author left that "API choice" open for maintainer acceptance. The write-path decision should settle one projection before adding mutations.
7. **Remote registry (later wave).** #4011's `remotes.toml`, pairing codes and per-entry `insecure` flag are the only concrete design and are unratified; the ratification routes remote access to #3340. Nothing in D1 to D3 contradicts the registry shape, but the plaintext policy in item 3 decides whether `insecure` can exist.
